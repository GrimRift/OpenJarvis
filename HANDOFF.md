## Important Decisions

- **Sandbox model**: every filesystem/coding/git tool is fail-closed —
  denies everything unless an `OPENJARVIS_*_DIRS` env var explicitly
  allowlists a root. Currently `C:\AI` (wide, by explicit user direction —
  "favor capability over caution," documented preference from this session).
  Sensitive files (`.env`, `*.pem`, `id_rsa`, `credentials.*`, etc., see
  `src/openjarvis/security/file_policy.py` /
  `rust/crates/openjarvis-security/src/file_policy.rs`) are blocked
  regardless of directory scope. **Preserve this fail-closed default** — do
  not make any tool permissive-by-default.
- **`git_commit` requires an explicit file list** — no `.`/wildcard staging,
  ever. This was a deliberate hardening decision, not an oversight; do not
  relax it to allow bulk-staging.
- **No credentials are ever entered by the assistant.** `TAVILY_API_KEY` and
  any future API keys are set by the user themselves via `setx` in their own
  terminal. The assistant only reads already-set env vars to forward them
  into subprocesses, and specifically avoided ever displaying the key value.
  **Codex should follow the same rule** — never ask for, type, or persist a
  credential value into a file on the user's behalf.
- **`requires_confirmation` on tool specs is currently a no-op** on the
  browser/API path and `jarvis ask` (both hardcode
  `confirm_callback = lambda prompt: True` — see
  `src/openjarvis/cli/ask.py` and `src/openjarvis/server/agent_manager_routes.py`).
  Only `jarvis chat`'s interactive terminal prompt is real. This was
  identified during M22 and the decision was: don't rely on it as a safety
  mechanism — real safety comes from each tool's own scoping/allowlisting,
  not from human-confirmation gating. This is a known, accepted gap, not
  something to "fix" without discussion — changing it would touch CLI/server
  code broadly and wasn't in scope for any milestone so far.
- **Citation convention for web results**: web_search results are cited as
  plain URLs in prose text. Local-knowledge-base `search` hits keep the
  existing `[N]` bracket + `ref_to_source` numbered-citation system
  (`research_loop.py`). These are deliberately *not* unified into one
  citation system — see the M24 design note in `research_loop.py`'s module
  docstring / `SYSTEM_PROMPT` for the reasoning (avoiding a parallel
  citation-shaping subsystem for `SearchHit`-shaped vs. Tavily-shaped data).
- **Two separate "research" agents exist in this codebase** and look
  similar from the outside but are NOT the same code:
  `agents/deep_research.py` (`DeepResearchAgent`, used by managed/persistent
  agents) vs. `agents/research_loop.py` (`ResearchAgent`, used by the
  browser's Deep Research button and `jarvis ask --research`). A fix to one
  does NOT automatically apply to the other — this caused real confusion
  mid-session (see "Current Status").
- **The Sage server process must be restarted after any config.toml or code
  change** for it to take effect — config/tools are loaded once at startup,
  not hot-reloaded. Multiple times this session a stale-running server
  caused confusing "it doesn't work" reports that were actually just a
  restart-needed situation, not a real bug.
